# SAM2.1 Tiny 部署与操作指南

适用于当前 Windows 本机 CPU 项目。本文已移除旧部署路径、安装过程流水账和失效的结果引用；当前检查范围以 [STATUS.md](STATUS.md) 为准。

## 目录约定

- 根目录 `README.md` 是项目入口；本文和 `STATUS.md` 位于 `docs/`。
- 自定义运行脚本位于 `scripts/`；历史依赖基线位于 `requirements/baseline.txt`。
- 原始图像、提示与结果分别保存在 `datasets/`、`inputs/`、`outputs/`。
- `.venv/` 与 `sam2/` 保持原位，避免破坏环境和可编辑安装路径。
- 本文命令均从**项目根目录**运行，不要在 `docs/` 或 `scripts/` 中直接照抄相对路径。
- 新目录重建时也保留 `scripts/` 层级；`run_image.py` 用脚本所在目录的上一级定位项目根目录。

## 1. 能做什么

当前入口使用人工矩形框提示进行单图分割，一颗目标牙一个框，输出独立二值掩膜。支持同图多个框，但不自动消除实例重叠，不识别临床牙位。

不支持界面点击、前景/背景点输入、病历文本、自动逐牙检测或训练。官方仓库具备其他能力，不等于当前入口已经集成。

## 2. 进入项目与检查环境

在项目根目录打开 PowerShell；本次检查时项目位置为：

```powershell
Set-Location -LiteralPath 'D:\Documents\projects\sam2-tiny-deployment'
& .\.venv\Scripts\python.exe --version
& .\.venv\Scripts\python.exe .\scripts\run_image.py --help
```

迁移项目后将第一行改为实际路径。无需激活环境。若 `.venv` 无法启动，先检查其依赖的基础 Python 是否存在，不要直接覆盖现有环境。

`.venv/pyvenv.cfg` 仍含旧创建路径，且环境依赖本机外部解释器，因此不能直接复制到其他电脑使用。

## 3. 先做合成图检查

```powershell
& .\.venv\Scripts\python.exe .\scripts\run_image.py --smoke --output .\outputs\smoke-001
```

如果目录已经存在，更换编号。完成后立即检查 `$LASTEXITCODE` 为 `0`，且输出包含 `mask_001.png`、`overlay.png`、`record.json`。仅有目录不算成功：脚本在读取输入和加载模型前便创建输出目录，失败后可能留下空目录或部分文件。

合成输入只是一个矩形，用于确认模型加载、编码、预测与保存链路，不属于牙片质量实验。本轮清理没有自动运行此命令。

## 4. 使用保留的单牙提示

图像：`datasets/pilot-5/images/DP100130_panorama.png`，尺寸 1722 × 922。

查看当前提示：

```powershell
Get-Content -LiteralPath '.\inputs\DP100130\prompts.json'
```

当前内容为：

```json
{
  "boxes": [
    [834.5449735449733, 566.2910052910049, 864.1746031746031, 657.2962962962961]
  ]
}
```

当前提示由图像旁的原始矩形标注 JSON 转换而来，保留小数坐标。原先 `[835, 564, 865, 659]` 提示已备份到 `inputs/DP100130/prompts-manual-001.json`，对应已有 `DP100130-single-001` 输出；新提示已运行，结果位于 `outputs/DP100130-annotated-001/`；另外五张图也各有对应的 `annotated-001/` 结果。其余五张图也已在 `inputs/<样本编号>/prompts.json` 中生成对应提示。

四个数依次为左边界 x、上边界 y、右边界 x、下边界 y，单位为原图像素。左上角为原点，x 向右、y 向下增加。这是保留的输入，运行前仍应在原图上核对目标位置，不应视为已审核的轮廓真值。

运行：

```powershell
& .\.venv\Scripts\python.exe .\scripts\run_image.py --image .\datasets\pilot-5\images\DP100130_panorama.png --prompts .\inputs\DP100130\prompts.json --output .\outputs\DP100130-001
```

也可使用封装脚本（需本机允许执行 PowerShell 脚本）：

```powershell
.\scripts\run.ps1 -Image .\datasets\pilot-5\images\DP100130_panorama.png -Prompts .\inputs\DP100130\prompts.json -Output .\outputs\DP100130-002
```

直接调用 Python 无需修改 PowerShell 脚本执行策略。每次只选一种方式并使用新输出目录。

## 5. 查看结果与解释记录

```powershell
Invoke-Item -LiteralPath '.\outputs\DP100130-001\overlay.png'
```

| 输出 | 含义 |
|---|---|
| `mask_001.png` 等 | 白色为预测目标，黑色为背景，尺寸与原图一致 |
| `overlay.png` | 彩色叠加预览，需与原图对照审核 |
| `record.json` | 提示、模型版本、文件指纹、耗时、分数等 |

脚本不会生成提示预览图或局部放大图。

检查顺序：确认目标牙 → 检查牙冠、牙根、根尖 → 检查相邻牙和背景外溢 → 检查碎片、孔洞和不合理截断。临床模糊边界须由专业人员判断。

记录解释：

- `load_seconds`：建立模型及加载权重的时间。
- `encode_seconds`：整张图编码时间。同图多个框复用该编码。
- `decode_seconds`：单个框的预测时间。
- 这些时间不覆盖程序启动、导入、结果保存、画框或审核，不应直接当作端到端总耗时。
- `model_score_not_accuracy` 是模型内部质量估计，不是准确率。
- `mask_pixels` 是预测前景面积，不是正确像素数。
- `image_sha256` 根据解码并转为 RGB 后的像素字节计算，不是原始图像文件的 SHA256。
- 当前脚本未接入人工真值，`ground_truth_available` 为 `false`，`accuracy_metrics` 为空。

原始模型输出与人工修订应分开保存，不得将未审核结果直接当作可靠伪标签。

## 6. 调整提示与同图多牙

复制提示文件后再修改，目标副本已存在时换名：

```powershell
Copy-Item -LiteralPath '.\inputs\DP100130\prompts.json' -Destination '.\inputs\DP100130\prompts-v2.json'
notepad '.\inputs\DP100130\prompts-v2.json'
```

在能显示原图像素坐标的工具中确认框。不要从缩放截图直接估算。要求：

- `0 <= x1 < x2 <= 图像宽度`
- `0 <= y1 < y2 <= 图像高度`
- JSON 使用英文标点，不含注释或末尾多余逗号。

框应尽量包含牙冠、牙根和根尖，同时减少无关区域。框是位置提示，不是轮廓真值或强制裁剪边界；缩小框不保证消除外溢。

多个框的结构示例（必须替换为人工核对的实际坐标）：

```json
{
  "boxes": [
    [100, 100, 150, 250],
    [160, 100, 210, 250]
  ]
}
```

第一个框对应 `mask_001.png`，第二个对应 `mask_002.png`；编号只是实例顺序。修改运行命令的 `--prompts` 和 `--output` 后运行。保持图像、模型与线程设置不变，一次只调整一种因素，记录修改原因并逐个审核掩膜。

## 7. 多图实验

`datasets/pilot-5/images/` 当前实际有 6 张图，目录名称不代表已完成五图实验。

1. 固定样本清单与选择理由，不按结果好坏偷偷换样本。
2. 每张图独立画框并建立提示文件，不复用上一张的坐标。
3. 每次使用独立输出目录，保留原始预测和错误信息。
4. 分别记录画框、进程总耗时、审核时间、内存观察方式和失败类型。
5. 有独立人工轮廓真值后再设计 Dice/IoU 评估；调优样本不能再充当独立测试集。

先单牙，再同图多牙，最后扩展固定多图样本。CPU 可执行不代表临床分割质量或效率已经达标。

## 8. 环境检查与常见问题

```powershell
& .\.venv\Scripts\python.exe -c "import sys, torch, torchvision, numpy, PIL; print(sys.version); print(torch.__version__); print(torchvision.__version__); print(numpy.__version__); print(PIL.__version__); print(torch.cuda.is_available())"
git -C sam2 rev-parse HEAD
Get-FileHash -LiteralPath '.\sam2\checkpoints\sam2.1_hiera_tiny.pt' -Algorithm SHA256
```

当前版本与指纹见 `STATUS.md`。CPU 环境显示 CUDA 为 `False` 属正常现象。

| 问题 | 处理 |
|---|---|
| 输出目录已存在 | 更换编号，避免覆盖 |
| 只有输出目录，没有完整文件 | 保留错误，修正后用新目录重试 |
| 导入或启动较慢 | 等待进程结束，勿反复启动同一任务 |
| 找不到 sam2 包或配置 | 用项目 `scripts/` 下的 `run_image.py`，不要随意改官方目录结构 |
| NumPy 数组只读警告 | 记录警告并核对进程状态与输出；不能据此推断分割质量 |
| 缺少 git，最终记录写入失败 | 脚本依赖 git 获取提交号；即使已有掩膜，也应补齐环境后重新运行 |
| 虚拟环境无法启动 | 核对外部基础 Python，必要时在新目录重建 |

## 9. 如需重新部署

不要在当前可用环境中重复安装。新电脑应使用其自身 Python 3.12，在新目录重建；保留 `scripts/run_image.py`、`scripts/run.ps1` 和需要的输入数据。

以下是 CPU 路线的重建参考，不代表本轮已经执行或验证。需要访问官方网络源。

```powershell
# 将此路径替换为新电脑实际的 Python 3.12
$basePython = 'C:\path\to\Python312\python.exe'
& $basePython --version
& $basePython -m venv .venv
& $basePython -m pip --python '.\.venv\Scripts\python.exe' install setuptools wheel
& $basePython -m pip --python '.\.venv\Scripts\python.exe' install torch==2.5.1 torchvision==0.20.1 --index-url https://download.pytorch.org/whl/cpu
& $basePython -m pip --python '.\.venv\Scripts\python.exe' install numpy==1.26.4 pillow==12.3.0 tqdm hydra-core iopath
git clone https://github.com/facebookresearch/sam2.git sam2
git -C sam2 checkout 2b90b9f5ceec907a1c18123530e92e794ad901a4
$env:SAM2_BUILD_CUDA = '0'
& $basePython -m pip --python '.\.venv\Scripts\python.exe' install --no-deps --no-build-isolation -e '.\sam2'
New-Item -ItemType Directory -Force '.\sam2\checkpoints' | Out-Null
curl.exe -L --fail --retry 2 -o '.\sam2\checkpoints\sam2.1_hiera_tiny.pt' 'https://dl.fbaipublicfiles.com/segment_anything_2/092824/sam2.1_hiera_tiny.pt'
& $basePython -m pip --python '.\.venv\Scripts\python.exe' check
```

这里采用历史 NumPy 1.26.4 基线；当前保留环境导入的是 2.5.2，二者不应混称为相同环境。`requirements/baseline.txt` 也是历史基线，不是本轮重新生成的依赖快照，其中可编辑 Git 安装行不宜直接替代本地仓库安装步骤。

若创建环境时仅 ensurepip 失败，先确认目标解释器能启动，再使用支持 `--python` 参数的基础 pip 安装；若环境未建成，先解决创建失败。`pip check` 只检查依赖声明，之后仍须核对权重指纹、运行合成图及真实图预测。

## 10. 清理约定

历史安装日志和项目根缓存已删除，清理前的预测结果不保留。当前 `outputs/DP100130-single-001/` 是整理后新生成的单牙结果。保留图像、提示、权重、源码与环境，不清理依赖或官方仓库内部缓存。

今后的结果按独立目录保存；失败或需要回溯的运行先记录再决定是否删除。本文不再引用已不存在的历史输出作为验收依据。
